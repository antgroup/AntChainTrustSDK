# AntChainTrustSDK 1.1.1

Release date: 2026-10-26. This patch release fixes issues found after v1.1.0.
See the [changes since v1.1.0](https://github.com/antgroup/AntChainTrustSDK/compare/v1.1.0...v1.1.1).

## Fixes

- Release checks select the previous stable ancestor, parse complete public
  declarations, and use current release tooling to validate historical tags
  ([#2](https://github.com/antgroup/AntChainTrustSDK/issues/2)).
- Failed core initialization cleans up signing keys and permits recovery
  ([#3](https://github.com/antgroup/AntChainTrustSDK/issues/3)).
- Credential access failures preserve the AWS runtime identity
  ([#4](https://github.com/antgroup/AntChainTrustSDK/issues/4)).
- KV v2 validates configuration limits and serialized record sizes
  ([#5](https://github.com/antgroup/AntChainTrustSDK/issues/5)).
- Issue and pull request templates, README navigation, and release validation
  documentation are available
  ([#6](https://github.com/antgroup/AntChainTrustSDK/issues/6)).

## Compatibility and validation

The compatibility baseline is **v1.1.0**. Release gates require public API,
exported symbol, and public header ABI checks against that tag, offline unit
and package tests, bundle metadata and checksum checks, Doxygen generation,
and successful signing and signature verification.

KV v2 requires `CONFIG_ACTRUST_KV_MAX_KEY_LEN=32`, matching the persisted key
layout. Builds that configured another value now fail explicitly; the default
configuration and storage format are unchanged.

The downloadable SDK bundle targets Linux x86. Linux ARM and Android
`arm64-v8a` CI checks cover cross-compilation and object architecture only.
They do not establish device runtime behavior. SIMCom hardware, AWS/PKI
integration, external-network tests, and hardware-backed security are outside
the release gates.

## Artifacts and verification

The release workflow publishes the Linux x86 SDK bundle, its SHA-256 checksum
and detached ECDSA P-256/SHA-256 signature, the public verification key,
`THIRD_PARTY.json`, and `sbom.spdx.json`. License notices and dependency metadata
are also included in the bundle. GitHub's generated source archives are
separate from this SDK bundle.

Download the bundle, `.sha256`, `.sig`, and
`actrust-release-p256-public.pem` from the
[v1.1.1 release](https://github.com/antgroup/AntChainTrustSDK/releases/tag/v1.1.1)
into one directory, then run:

```bash
sha256sum -c AntChainTrustSDK-1.1.1-linux_x86.tar.gz.sha256
openssl dgst -sha256 -verify actrust-release-p256-public.pem \
  -signature AntChainTrustSDK-1.1.1-linux_x86.tar.gz.sig \
  AntChainTrustSDK-1.1.1-linux_x86.tar.gz
```

The signature check must report `Verified OK`. The verification key is also
tracked in the
[release source](https://github.com/antgroup/AntChainTrustSDK/blob/v1.1.1/tools/release/actrust-release-p256-public.pem).
Its SHA-256 fingerprint, computed over the DER-encoded SubjectPublicKeyInfo,
is:

```text
53977e1b161d64dc97ca46d7bd4006604c078572234bcde3f807e26fdba05f0d
```

Check the downloaded key against this fingerprint from a trusted copy of the
release documentation:

```bash
openssl pkey -pubin -in actrust-release-p256-public.pem -outform DER \
  | openssl dgst -sha256
```

Generate API documentation from a v1.1.1 checkout with `doxygen Doxyfile`, then
open `docs/v1.1.1/html/index.html`.
